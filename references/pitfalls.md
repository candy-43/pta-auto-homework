## P1 域名混淆：pintian.cn ≠ pintia.cn

- **现象**：用户口述"打开 pintian.cn"。该域名 DNS 指向 `overdue.aliyun.com`，页面实际是 "pintian.cn is For Sale"（域名待售页），HTTP 80 返回 403、HTTPS 443 直接被掐。
- **根因**：多打了一个 `n`。正确域名是 **pintia.cn**（拼题A，杭州 PAT 教育科技公司，浙ICP备17025079号-1）。
- **处置**：
  - 用户给出域名后，先 `curl -sI` 或 WebSearch 快速验证；若发现 "For Sale" / `overdue.aliyun.com` / 403 WAF 页，立即怀疑拼写并向用户要完整 URL。
  - 不要在错误域名上反复重试诊断（本次在 pintian.cn 上花了多轮 DNS/curl/搜索才确认是死路）。

## P2 二维码有时效

- **现象**：微信登录二维码出现后若拖延截图/发送，可能过期。
- **处置**：见到 "Please use WeChat to scan this QR code" 后**立即** `screenshot` 并发送给用户；发送话术里写清"保存图片 → 微信扫一扫 → 相册选图"（手机端无法直接扫另一台设备的屏）。用户回复后用 snapshot 确认登录态（出现题集卡片）再继续。

## P3 编辑器禁用复制粘贴 → 必须键盘录入

- **现象**：用户明确要求"只能用键盘输入，不能复制粘贴"。
- **根因**：PTA 前端对 paste 事件有防护；同时剪贴板注入会绕过用户审计。
- **处置**：
  - 用 `agent-browser keyboard type "<code>"`（真实键盘事件），**不要**用 `keyboard inserttext`（无键盘事件，可能被编辑器忽略）。
  - 代码里的换行符 `\n` 会被映射为回车换行，缩进用空格不用 Tab。
  - 每次录入完必须 snapshot 回读编辑器内容核对。

## P4 Next / 侧边栏题号点击"被吞"

- **现象**：点击 `button "Next"` 后 snapshot 仍显示旧题；侧边栏点题号 "1" 却跳到了 "5"。
- **根因**：SPA 异步渲染期间点击事件丢失；且提交判题后页面 ref 全局重排，旧 ref 映射到新元素。
- **处置**：
  - **每次点击前重新 snapshot 取 ref**，绝不信缓存 ref。
  - 点击后用 `grep -E '2-[0-9]+ '` 验证标题真变了；没变就重取 ref 再点一次（实测第二次基本必成功）。
  - 连续切题可用"双击 Next"模式：click → sleep 4 → click → sleep 4 → 验证。

## P5 Monaco 编辑器 ref 不固定

- **现象**：代码编辑器 textbox 有时是 `e50`，有时是 `e51`（e50 被语言下拉框占用）。
- **处置**：永远动态定位，不要写死 ref：

```bash
editor=$(agent-browser snapshot | sed -n '/Stack size limit/,/Test Case/p' \
  | grep -oE 'textbox \[ref=e[0-9]+\]' | grep -oE 'e[0-9]+' | head -1)
```

注意：编辑器为空时 textbox 行和 LineBreak 行之间有空行，`grep -B1` 会漏，用上面的区间法更稳。

## P6 中文键盘输入必须回读核对

- **现象**：代码含中文（如 `print('今天是' + d + '...')`），逐键输入 CJK 字符存在丢字/错字风险。
- **处置**：`keyboard type` 后立刻 `snapshot | grep -A 4 "textbox \[ref=$editor\]"` 逐字核对中文字符串。实战 3 道中文题（2-10/2-11/2-13）均一次录入正确，但核对不能省。

## P7 判题排队（In queue / Waiting）

- **现象**：提交后结果面板显示 "In queue, 20 submissions ahead"、"Waiting"，Score 显示 "- / 5"。
- **根因**：高峰期评测机排队，属正常状态。
- **处置**：等 30~60 秒 → 点结果面板 `button "Reload"` → 再读状态。**严禁等不及就重复提交**（污染提交记录，部分课程按最后一次计分）。

## P8 提交按钮点击未生效 → 记录丢失

- **现象**：2-13 首次提交后，提交列表无记录、题目页显示 "No Submit Records"、编辑器代码被清空。
- **根因**：同 P4，提交那次 click 落在异步渲染空窗，实际没触发。
- **处置**：提交后必须在 **Submission list**（或结果面板）确认记录存在且状态正确；发现没提交成功 → 回题目页重新录入代码（编辑器已清空）→ 重交。收尾时逐题核对提交列表，不要只看侧边栏进度。

## P9 提交按钮的 disabled 态

- **现象**：`button "Submit For This Problem" [disabled, ...]`。
- **根因**：编辑器无代码时按钮不可用。
- **处置**：先录入代码再取按钮 ref；若仍 disabled，说明代码没进编辑器，回 P3/P5 检查。

## P10 读题不全：折叠段落与歧义描述

- **现象**：2-13 题干部分内容折叠（有"收起"按钮）；2-1/2-2 题面"控制每个整数的输出长度"表述有歧义。
- **处置**：
  - 见到"收起"按钮说明有折叠区，展开读全文。
  - 题面歧义时**以输入输出样例为准**：如 2-1 样例 `3*5= 15`（只有乘积补位），2-2 样例 `3  *5  =15 `（每个数含乘积都补位，且行尾有空格）。逐字符对照样例构造 format 串。

## P11 输出样例的隐形字符

- **现象**：2-2 输出 `3  *5  =15 ` 行尾有 1 个空格；2-7 输入 `3, 5` 逗号后有空格。
- **处置**：snapshot 输出样例时注意 textbox 值的结尾（`-A` 多看几行）；PTA 默认忽略行尾空白，但按样例精确复刻最稳。`split(',')` + `int()` 可自动吃掉逗号后的空格。

## P12 agent-browser 自身的操作坑

- **现象/处置**：
  - `screenshot --path xxx` 会把 `--path` 当选择器报 "Element not found" → 正确语法是 `screenshot <selector> <path>`，全页截图直接 `screenshot /abs/path.png`。
  - `wait --load networkidle` 在 SPA 上可能一直不空闲 → 降级 `wait --load load` 或直接 snapshot。
  - 打开 `http://` 明文 URL 可能报 `ERR_BLOCKED_BY_CLIENT` → 沙箱网络对部分目标 443 也会 `ERR_CONNECTION_CLOSED`，此时 `curl` 存页面再 `open file://` 本地渲染可验证内容（仅用于诊断，正式流程走 https）。
  - daemon 偶发 `CDP command timed out` → `agent-browser close` 后重开即可，登录态在 cookie 里不丢。

## P13 切题点击全面失效：提交结果浮层遮挡

- **现象**：做完一题后，点侧边栏题号或 `button "Next"` 页面毫无反应，标题始终停在旧题；按 P4 的"重取 ref 再点一次"同样无效。
- **根因**：提交后弹出的判题结果面板是浮层，覆盖在侧边栏与 Next 按钮上方，点击事件被浮层拦截，根本没落到按钮上。
- **处置**：绕开点击，直接 URL 导航。先从页面 a 标签提取真实题目 ID：

```bash
agent-browser eval "Array.from(document.querySelectorAll('a')).filter(a=>/problemSetProblemId/.test(a.href)).map(a=>a.textContent.trim()+':'+a.href.split('=')[1]).join(' ')"
```

然后直接 open 目标 URL（`https://pintia.cn/problem-sets/〈setId〉/exam/problems/type/7?problemSetProblemId=〈id〉`）。**附带收获**：同一题集内这些 `problemSetProblemId` 连续递增（本次从 `...240` 到 `...259`），拿到首题 ID 即可推算全部题目，比逐题点击稳定得多。

## P14 keyboard 子命令不支持快捷组合键

- **现象**：用 `agent-browser keyboard "Control+a"` 想清空编辑器，直接报错 `Valid options: type, inserttext`。
- **根因**：`keyboard` 子命令只接受文本输入——`type`（逐键真实事件）与 `inserttext`（无事件插入），**不处理快捷键组合**。
- **处置**：改用 `press` 命令（专门做按键与组合键）：

```bash
agent-browser press "Control+a"    # 全选
agent-browser press "Backspace"    # 删除
```

这是逐题清空编辑器的高效手段。切题后编辑器会保留上一题代码，先 `Control+a` + `Backspace` 清空再录入，可避免残留代码干扰。

## P15 编辑器自动补全引号，三引号写法被破坏

- **现象**：用三引号 `"""..."""` 写多行输出（如输出古诗），录入后核对发现末尾变成 `苍苍。""""")`——多出一组引号，直接语法错误。
- **根因**：编辑器有括号/引号自动配对功能。逐键输入 `"` 时编辑器自动补配对 `"`，三个 `"` 敲完就多出一组。
- **处置**：多行文本改用**逐行 `print("...")`**，规避三引号嵌套与自动补全干扰。

## P16 照抄题必须先本地跑：%s 里的字符串字面量

- **现象**：题目给定 `print("Its fleece was white as %s." % 'snow')`，误以为"要输出带单引号的 'snow'"，写成 `% (chr(39) + "snow" + chr(39))`，本地跑出 `as 'snow'.`，与样例 `as snow.` 不符。
- **根因**：对 `%` 格式化的理解偏差。`'snow'` 是 Python **字符串字面量**，其值就是 `snow`（不含引号）；`%s` 只把值原样插入，不会带上引号。
- **处置**：改回普通字符串 `"snow"` 即可。凡"题目直接给了代码"的照抄题，务必先在本地 `python3` 跑一遍比对样例输出，不要凭直觉改写。

## P17 题干文字与样例冲突：一律以样例为准

- **现象**：4-19「两数之商」题干写"计算结果保留2位小数"，但样例 18/3 输出的是 **6.0** 而不是 6.00。按题干用 **%.2f** 提交，结果 **Partially Accepted 3/5**（普通测试点 WA，除零测试点 AC）；改成直接 **print(a/b)** 后满分。
- **根因**：出题人手写样例时往往不严谨，样例可能与"输出格式"文字描述不一致。PTA 测试点按出题人实际生成的期望输出比对，而这份期望输出通常与样例一致，**不与文字描述一致**。
- **判据**：样例 > 文字描述。当二者矛盾时，把样例的每个字符（含空格、标点、尾随零、小数位数）当作唯一验收标准。
- **延伸**：**print** 的多参数形式会自动在参数间插入一个空格。样例 4-20 第一行 **面积为： 16.2**（冒号后有空格）、第二行 **面积为：16.20**（无空格）——同一题两种空格写法并存，必须逐行比对样例，不能只抄第一行套用到底。
- **处置**：读到"见样例""输出格式如示例"时，先逐字符拆解样例输出（空格、标点、位数），再决定格式化写法。本地跑不能发现问题（本地是按题干实现，跑出来自然符合题干），**只有比对样例才能发现**。

## 判题状态速查

| 状态 | 含义 | 动作 |
|------|------|------|
| Accepted | 通过 | 下一题 |
| Wrong Answer | 答案错 | 逐字符比对样例，改码重交 |
| Compile Error | 编译错 | 回读代码查语法（常见：录入丢字符） |
| Waiting / In queue | 排队 | 30~60s 后点 Reload，勿重交 |
| Runtime Error | 运行崩 | 查输入解析（int/float、split） |
